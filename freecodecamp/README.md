# freeCodeCamp skeletons

One skeleton per chapter, mirroring `docs/` file-for-file. Each skeleton keeps the chapter's headings and order, reduces every paragraph to a single telegraphic note, and replaces each code block with a bracketed marker describing what the snippet shows.

These are **not drafts**. freeCodeCamp's style guide requires article text to be the author's own writing; AI help is fine for ideation and for basic code samples that the author then tests and runs. So the workflow for each piece is:

1. Pick a skeleton and rewrite it into your own prose, in your own voice.
2. When you reach a `[Code: ...]` marker, pull the real snippet from `src/` (or the chapter in `docs/`), run it, and adapt it as needed.
3. Send Remy your draft for editorial feedback — structure, clarity, technical accuracy — not rewriting.

Remember freeCodeCamp doesn't usually run multi-part series, so most of these will need to stand alone as individual tutorials (or eventually be reworked into one big guide/handbook). The chapter trailers and cross-references in the originals are the parts most likely to need cutting or reworking for that.
